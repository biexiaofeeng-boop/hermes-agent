# AuthGate v2 设计方案（基于 OpenClaw 借鉴）

- 日期: 2026-02-20
- 目标: 在不牺牲安全前提下，显著降低审批噪音，形成移动端可操作、可追踪、可扩展的授权体系。
- 参考: `05-OpenClaw-Auth-Design-Compare-Report-2026-02-20.md`

## 1. 设计目标

1. 把“工具级一刀切拦截”升级为“策略级分层决策”（安全、体验、可运维平衡）。
2. 支持移动端主流程：Telegram 可直接审批，且审批后可自动续跑任务。
3. 审批权限与普通用户权限解耦：审批人白名单 + 审批作用域。
4. 授权决策可沉淀（allow-always / allow-ttl），降低重复审批。

## 2. 目标架构（借鉴 OpenClaw 的最小可行版）

### 2.1 核心组件

1. `AuthPolicyEngine`（策略引擎）
   - 输入: toolName、params、session/user/context
   - 输出: `allow | ask | deny`
   - 策略维度:
     - `security`: `deny | allowlist | full`
     - `ask`: `off | on-miss | always`
     - 工具特定策略（exec / write / edit / message）

2. `ApprovalManager`（审批生命周期）
   - 管理 `request -> pending -> resolved/expired`
   - 决策类型: `allow-once | allow-session | allow-ttl | allow-always | deny`
   - 提供等待与恢复执行需要的状态查询

3. `ApprovalRuleStore`（审批记忆库）
   - 存储长期/短期规则（session/ttl/always）
   - 用于命中即放行，减少重复审批

4. `ApproverACL`（审批人 ACL）
   - 独立于 channel allowFrom
   - 限制谁可以 `/approve`、`/reject`

### 2.2 数据文件建议

在 `chimera-bridge/auth/` 下新增：

- `policy.json`
  - 存放默认策略（security/ask）与 per-tool 规则
- `rules.json`
  - 存放 allow-session / allow-ttl / allow-always 规则
- `pending_auth.json`
  - 继续沿用，记录当前待审批请求
- `audit_auth.jsonl`
  - 继续沿用，完整审计链路

## 3. 决策模型（拿来主义落地）

### 3.1 决策顺序

1. **ACL 预检**：审批命令发起人是否在 `ApproverACL`
2. **硬拒绝**：命中 deny patterns / 危险工具组合
3. **规则命中放行**：命中 rules（session/ttl/always）
4. **策略判定**：根据 security + ask 产出 `allow/ask/deny`
5. **ask 路径**：创建 pending request，发通知并等待决策

### 3.2 `exec` 默认策略（balanced）

- `security=allowlist`
- `ask=on-miss`
- 命中 safe_prefixes + 无危险 token → allow
- 否则 ask
- 命中 deny_patterns / shell control 链式执行 → deny 或 ask(高危)

### 3.3 非 exec 工具策略

- `write_file/edit_file`:
  - 按路径分级（workspace allow、敏感路径 ask/deny）
- `message`:
  - 私聊可放行，群发/外部目标 ask

> 注: 当前阶段可先保留 write/edit/message 审批，再逐步切路径策略。

## 4. 审批语义（v2）

审批命令支持：

- `/approve <id> once`
- `/approve <id> session`
- `/approve <id> ttl 6h`
- `/approve <id> always`
- `/reject <id> <reason>`

语义说明：

- `once`: 仅本次参数哈希放行（现有能力）
- `session`: 当前 session 内同类请求放行
- `ttl`: 指定有效期内放行
- `always`: 持久规则放行（可撤销）

## 5. 自动续跑（关键体验项）

当前问题：审批后用户要重发请求。

v2 方案：

1. 触发 ask 时，保存“待执行上下文”（session/tool/params/trace）。
2. 审批通过后由 `ApprovalManager` 发送 resume 事件。
3. AgentLoop 接收 resume 事件并继续执行原请求。
4. 给用户返回“已批准并继续执行”确认消息。

## 6. Approver ACL 设计

在配置中新增：

```json
"authGate": {
  "approvers": {
    "enabled": true,
    "allowFrom": ["8464732775", "telegram:8464732775"],
    "allowGatewayScopes": ["operator.approvals", "operator.admin"]
  }
}
```

规则：

- 非 approver 发 `/approve` -> 拒绝 + 审计
- approver 可审批，但仍记录 `approvedBy`

## 7. 与 OpenClaw 的映射关系

1. `security + ask + allowlist` → chimera `AuthPolicyEngine`
2. `allow-once/allow-always/deny` → 扩展为 `once/session/ttl/always/deny`
3. `ExecApprovalManager` 生命周期 → chimera `ApprovalManager`
4. `/approve` sender+scope 校验 → chimera `ApproverACL`

## 8. 分阶段执行计划

### P0（先降噪，1-2天）

1. 默认策略切到 `exec balanced`；非 exec 保守但减少误触发。
2. 引入 `policy.json`，策略可配置化。
3. 完成回归测试补充（策略命中/误拦截/危险命令拦截）。

### P1（能力补全，3-5天）

1. 实现 `allow-session/allow-ttl/allow-always`。
2. 实现审批后自动续跑。
3. 上线 `ApproverACL`。

### P2（治理增强，可选）

1. write/edit 路径分层策略。
2. 审批规则可视化与撤销命令。
3. 状态 API 增加 auth 摘要统计项。

## 9. 需要新增/改造的代码位置

1. `nanobot/auth/gate.py`（拆分策略与审批管理）
2. `nanobot/agent/loop.py`（resume 执行钩子）
3. `nanobot/channels/telegram.py`（审批命令参数扩展）
4. `nanobot/config/schema.py`（policy + approvers + rules 配置）
5. `nanobot/cli/commands.py`（auth 子命令扩展：rules/list/revoke）

## 10. 验收指标（建议）

1. 24h 内审批触发率下降 >= 40%（同任务量对比）。
2. 高危命令拦截率 100%。
3. 审批后自动续跑成功率 >= 95%。
4. 非 approver 审批命令拒绝率 100%。
