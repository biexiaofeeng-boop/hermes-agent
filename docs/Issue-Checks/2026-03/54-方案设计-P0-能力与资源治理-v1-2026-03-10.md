# 方案设计：P0 能力与资源治理（Tavily-First + 资源边界）（v1）

- 日期：2026-03-10
- 状态：READY
- 关联问题单：`51`、`52`

## 0) 目标
1. 默认搜索链路切为 Tavily-first，并支持可观测降级。
2. 执行层/治理层/配置层语义完全对齐。
3. 资源边界（workspace/missionWorkspace/memory/外接SSD）统一成可检查基线。

## 1) 分阶段设计

### Phase A：搜索能力统一（P0-A）

#### A1. 配置模型升级
- 在 `nanobot/config/schema.py` 扩展 `WebSearchConfig`：
  - `provider`: `tavily|brave|auto`（默认 `tavily`）
  - `fallback_provider`: `brave|none`（默认 `brave`）
  - `tavily_api_key` / `tavily_api_key_ref`
  - `brave_api_key` / `brave_api_key_ref`
- 保留兼容：旧 `api_key/api_key_ref` 视为 brave 兼容字段（deprecated）。

#### A2. 工具执行升级
- 在 `nanobot/agent/tools/web.py` 将 `WebSearchTool` 改为 provider-aware：
  - 主路径：Tavily API
  - 兜底：Brave API（可禁用）
  - 输出中增加 `provider_used` 与 `fallback_used`（便于观测）

#### A3. Agent 注入参数升级
- `nanobot/cli/commands.py`、`nanobot/agent/loop.py`、`nanobot/agent/subagent.py`：
  - 不再传 `brave_api_key` 单值
  - 传入统一 `web_search_config`（provider + keys + fallback）

#### A4. 治理层对齐
- 在 `nanobot/capability/sync.py` 补充映射：
  - `tool:websearch-tavily` 的 adapter/meta 标注默认 provider
- 目标：`toolchain/capability` 状态与执行默认 provider 一致。

### Phase B：资源边界与 secrets 统一（P0-B）

#### B1. 统一 secrets 注入函数
- 新增：`deploy/runtime/load_secrets_env.sh`（或同等 helper）
- 被以下入口统一复用：
  - `deploy/chimera_ops_check.sh`
  - `deploy/chimera_daily_readiness.sh`
  - `deploy/s8-ops-pack/chimera_s8_acceptance.sh`

#### B2. 资源能力基线
- 新增治理文档（或 JSON 基线）：
  - workspace root
  - missionWorkspace 优先级
  - memory 路径
  - 外接 SSD 允许前缀
- 规则：
  1. `missionWorkspace` 优先于全局 workspace
  2. 默认禁止写入 missionWorkspace 之外（除非显式 allowlist）
  3. profile 切换时资源映射必须可追溯

#### B3. 巡检与判定标准
- `ops_check` / `daily_readiness` 增加：
  - 当前默认搜索 provider
  - key 注入来源是否齐全
  - workspace/missionWorkspace 一致性检查
- 输出示例应可直接用于日检回填。

## 2) 回滚设计
1. 搜索回滚：`provider=tavily -> brave`（配置切换）
2. secrets 回滚：入口脚本恢复原路径（保留 helper 可选）
3. 资源回滚：禁用 strict boundary，仅保留告警模式

## 3) 风险与控制
1. Tavily 降级抖动
- 控制：限制重试次数，明确 fallback 触发条件。
2. 兼容旧配置失败
- 控制：保留 deprecated 字段读取周期（至少一个迭代）。
3. 入口脚本变更影响线上
- 控制：先在 test profile 验证，再 prod 灰度。

## 4) 验收目标
- 治理显示 Tavily ready 时，执行默认一定走 Tavily。
- 无 Tavily key 时行为可预测（fallback 或显式失败）。
- 三类入口脚本 secrets 注入行为一致。
- 资源边界检查可复现且可回滚。
