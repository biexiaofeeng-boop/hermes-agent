## 设计原则（本轮强约束）

1. 默认先回答，不拦截。
2. 意图识别只做内部路由，不直接外露模板提示。
3. 允许模糊表达与发散讨论，不能强制用户补格式。
4. 建议必须具体可执行（对象+动作+产物）；泛化建议禁止输出。
5. 高风险执行按 `L0/L1/L2` 分层，优先“同会话短确认”，避免过度审批噪声。

## 风险分层（Guardrail 会话模式）

- `L0`（低风险 / 只读）：
  - 示例：`pwd`、`ls`、`git status`、只读查询。
  - 策略：不拦截，不确认。
- `L1`（中风险 / 工作区内可逆变更）：
  - 示例：工作区内临时文件清理、缓存重建、非关键目录 delete。
  - 策略：默认不走 AuthGate，仅在同会话给一行确认追问（可配置）。
- `L2`（高风险 / 越界或不可逆）：
  - 示例：跨工作区、系统级破坏、受保护路径/文件、资产库与记忆区变更。
  - 策略：先同会话短确认；仅在跨会话/长时授权/审计强制时升级完整 AuthGate（`auth-*`）。

## 验收标准（必须全部满足）

1. 用户对话中不再出现以下固定模板：
- “我先给你一个可执行方向……”
- “请补一句：目标 + 产物 + 是否直接执行……”
- 非必要 `[可选澄清]`

2. 模糊交流可正常互动：
- 对脑暴/开放讨论先回答，再在必要时给具体建议。

3. 建议质量达标：
- 任意建议均可映射到“对象+动作+产物”。

4. 安全边界不回退：
- `L2` 高风险不绕过；`L0/L1` 不过度弹 AuthGate 长提示。

5. 确认体验提升：
- `TaskConfirm` 文本必须与当前议题具体绑定，不得使用固定泛模板。

6. 回执体验提升：
- 默认不单独发送 `[CollabReceipt]`；必要时才显式发送，其他场景并入最终结果。
