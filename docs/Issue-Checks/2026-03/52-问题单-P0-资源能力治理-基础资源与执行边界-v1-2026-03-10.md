# 问题单：P0 资源能力治理（基础资源与执行边界）（v1）

- 日期：2026-03-10
- 状态：CHECK
- 归属：运营稳态治理（非本线程直接开发）

## 1) 问题描述

当前“基础能力/项目能力/资源能力”边界定义不够清晰，主要表现为：

1. 运营语义上希望“基础能力=默认可调用”，但实际分布在执行层/治理层/配置层多个位置；
2. 资源能力（workspace、memory、missionWorkspace、外接 SSD）缺少统一治理入口；
3. secrets 注入在不同入口脚本存在差异，导致检查与真实运行偶发不一致。

这会影响任务执行的稳定性和运维可解释性。

## 2) 影响范围

1. 基础能力盘点困难，导致任务编排前置假设不稳定。
2. 资源边界不清，存在“可执行但不该执行路径”风险。
3. 运维重启与巡检可能出现环境变量不一致问题。

## 3) 本问题单范围（In Scope）

1. 建立基础能力/项目能力/资源能力的统一分类与配置映射。
2. 资源能力治理（workspace 根、project missionWorkspace、memory 挂载、外接磁盘路径规范）。
3. 运行入口与巡检入口的 secrets 注入一致性标准。

## 4) 非范围（Out of Scope）

1. 项目模板具体内容设计（留给项目治理下一阶段）。
2. 新执行器能力研发（本单不扩展新执行器功能）。
3. 本线程直接代码实现与发布。

## 5) Plan Agent 输入约束

1. 优先“运营稳定”，不追求一次性大改架构。
2. 输出必须可分阶段发布（小步可回滚）。
3. 每个阶段都要有运行态验收命令与失败回退动作。

## 6) Checkpoints（验收检查点）

- [ ] C01 能力总表：输出基础能力清单（file/exec/system/web/search/rpa-vision/memory 等）及其真实代码入口。
- [ ] C02 三层映射：对每项能力标注执行层、治理层、配置层三处映射关系。
- [ ] C03 资源总表：输出资源能力清单（workspace/memory/missionWorkspace/外接SSD）及配置入口。
- [ ] C04 边界策略：定义 missionWorkspace 与全局 workspace 的优先级与保护规则。
- [ ] C05 secrets 一致性：定义 gateway 启动、ops_check、acceptance 三类入口统一注入规范。
- [ ] C06 重启策略：标注每类配置变更是否需要重启，给出“无重启/需重启”判定标准。
- [ ] C07 运营巡检项：补充日检/周检中的能力与资源一致性检查项。
- [ ] C08 回滚策略：资源路径、环境注入、能力开关三类回滚路径可独立执行。

## 7) 交付物要求

1. 问题拆解与分阶段方案（P0/P1）。
2. 运营配置基线模板（可直接用于 prod/test 对齐）。
3. Checklists（每日/每周）与异常 SOP 补充。
4. INDEX 回填与状态推进记录。
