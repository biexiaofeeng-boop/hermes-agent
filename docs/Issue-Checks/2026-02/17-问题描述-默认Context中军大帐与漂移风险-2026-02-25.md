# 问题描述：默认 Context 中军大帐与漂移风险

- 日期: 2026-02-25
- 面向对象: chimera-core-codex
- 问题等级: P0（默认执行稳定性）/ P1（路由可控性）

## 一、背景

T15 已完成项目路由、项目 pack 动态加载、mission workspace 执行隔离，但当前“默认会话起始态”仍存在结构性不足：

1. 默认态偏向项目回退（arb），不是中立的“中军大帐（Lobby）”。
2. 灵魂锚与价值观锚缺少“防漂移机制”，长期会话容易被业务噪声覆盖。
3. 路由仍以“项目 ID”主导，尚未充分体现“任务类型域（创作/工程/运营/教育）优先”。
4. 默认 memory 负载偏重，可能挤压执行契约与元认知路由信息。
5. Lobby 模糊指令缺少“先澄清再执行”的统一策略，易出现误执行或体验抖动。
6. 工具链路结束但模型未产出自然语言时，存在“空回复”体验（容易被误判为系统 down）。

## 三、根因归纳

1. **默认态定义缺失**：有项目态（pack）但缺“中立大厅态（Lobby）”的显式模型。
2. **锚点分层不完整**：灵魂锚、元认知锚、能力锚未形成固定层级与比例。
3. **路由粒度偏粗**：直接 project 命中，不利于跨项目复用能力域。
4. **配置可调性不足**：当前缺少默认态路由策略和 memory 注入强度的显式配置项。

## 四、影响

1. 对执行质量：默认起手可能被误导到具体项目，影响准确路由。
2. 对认知一致性：长期会话下灵魂锚与价值观锚可能被稀释。
3. 对可扩展性：未来新增多个项目时，按项目硬匹配会放大维护成本。
