## 目标

1. 把“已完成能力”转成可复用场景模板，降低日常使用成本。
2. 固化 6 类高频场景的任务编排（创建 -> 执行 -> 回写 -> 复盘）。
3. 让 TaskOps 成为统一入口：同一套模板可跑日常运营与迭代任务。

## 6 类场景范围

1. `file&shell`：文件与终端批处理。
2. `data_collect_classify`：采集、归档、标签化到指定路径。
3. `web_access`：websearch/webfetch + 账号前置检查。
4. `codex_claude_collab`：协作开发任务拆分与回写。
5. `content_ip_ops`：内容创作与 IP 运营节奏执行。
6. `hf_github_ai_watch`：HuggingFace/GitHub 关键词追踪与日报。

## 交付物

1. 场景模板目录（建议）：`chimera-bridge/taskops/templates/*.json`。

## 开发标准（必须）

1. 配置驱动：模板不写死账号/密钥/机器路径。
2. 幂等执行：重复触发不会破坏已有产物（可覆盖/可跳过需可配置）。
3. 可追溯：每次模板执行必须写 runlog（含输入、版本、结果）。
4. 兼容优先：不破坏现有 `taskops.*` 与 auth gate 主路径。
5. 风险隔离：高风险动作仍遵循现有 mission/auth 语义。

## 测试标准（自动化）

1. 单测：模板 schema 校验、参数渲染、默认值与缺省错误路径。
2. 控制面测试：模板创建/预览/投递任务的 RPC 覆盖。
3. smoke：至少 2 个模板跑通（一个 bot 任务、一个 human 任务）。
4. 全量回归：`bash deploy/chimera_core_test.sh` 必须通过。

## 联调标准（手工）

1. 连续 1 天使用至少 3 个模板场景。
2. 每个场景至少 1 条成功 runlog + 1 条异常分支记录。
3. 人机分流可见：human 任务有通知、bot 任务可自动推进。
4. 出现失败时可通过日志定位到模板参数或能力缺口。
