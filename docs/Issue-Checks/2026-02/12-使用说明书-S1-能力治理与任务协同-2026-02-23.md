## 3. 工具链治理（含 1Password 扩展）

### 3.1 当前事实（基于代码与配置）

- Web 搜索工具运行时使用 `BRAVE_API_KEY`：`/Users/sourcefire/X-lab/chimera-core/nanobot/agent/tools/web.py`
- Toolchain 默认有 `websearch-tavily`，但默认 `enabled=false`：`/Users/sourcefire/X-lab/chimera-core/chimera-bridge/toolchain/registry.json`
- 默认工具链没有 `1password` 项，需要手动补登记。

### 3.2 把 1Password 纳入能力治理

```bash
python3 - <<'PY'
from pathlib import Path
import json

path = Path('/Users/sourcefire/X-lab/chimera-core/chimera-bridge/toolchain/registry.json')
data = json.loads(path.read_text(encoding='utf-8'))
tools = data.setdefault('tools', [])

if not any(t.get('id') == '1password-cli' for t in tools):
    tools.append({
        'id': '1password-cli',
        'name': '1Password CLI',
        'category': 'service',
        'enabled': True,
        'authRef': 'OP_SERVICE_ACCOUNT_TOKEN',
        'healthCheck': 'op --version',
        'riskLevel': 'medium'
    })
    path.write_text(json.dumps(data, indent=2, ensure_ascii=False) + '\n', encoding='utf-8')
    print('added 1password-cli')
else:
    print('1password-cli already exists')
PY

nanobot toolchain check --tool 1password-cli
nanobot capability sync --from toolchain
nanobot capability check --id service:1password-cli
```

## 4. 任务协同主流程（bot/human 分流）

### 4.1 建任务（带能力与执行器约束）

```bash
nanobot taskops add --title "生成 AI 情报日报（HF+GitHub）" --owner-type bot --project ai-intel --priority 1 --difficulty 3 --description "采集并汇总 HuggingFace 与 GitHub 新项目，输出日报到指定目录" --acceptance "输出 markdown 报告，含来源链接、风险标注、下一步建议" --required-capabilities service:github,executor:codex --preferred-executor executor:codex --fallback-executors executor:claude,local-tools

nanobot taskops feasibility --limit 200
nanobot taskops board
```

### 4.2 运行自动分发（dispatcher/notifier）

```bash
# 方式A：直接运行

# 方式B：部署脚本（含 stop/restart）
```

- human `todo` 任务会按冷却策略通知到配置通道（如 Telegram）。

## 5. 授权噪音控制（避免“普通交流也频繁授权”）

### 5.1 先确认当前策略模式

```bash
nanobot status
nanobot auth rules --status active
```

- 当 `execPolicy.mode=guardrail` 时：仅“红线命令”触发授权。
- 当 `execPolicy.mode=strict` 时：几乎所有 `exec` 都触发授权。

### 5.2 长任务建议使用 mission scope，降低重复申请

```bash
nanobot auth mission-grant --by manual --principal telegram:8464732775 --session telegram:8464732775 --ttl 8h --mission-id s1-daily-ops --node main --workspace /Users/sourcefire/X-lab/chimera-core
```

## 6. 每日/每周运营节奏（建议）

### 每日（10~20 分钟）

1. `toolchain status/check` + `capability check`。
2. `taskops feasibility` 看阻塞任务。
3. `taskops board` + 人工清理 blocked 原因。
4. `auth list --status pending` 处理堆积请求。

### 每周（30~60 分钟）

1. 清理 toolchain 中长期禁用能力。
2. 对比 `capability runs` 与 `taskops runs` 找薄弱点。
3. 回填文档与案例库，沉淀可复用任务模板。
